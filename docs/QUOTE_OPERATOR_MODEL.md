# EVENTO Gate 3 — Quote Operator Model

Status: design/implementation contract for Recovery branch. No privileged operator UI is activated yet.

## Purpose

EVENTO must be able to turn an approved customer scope into a versioned AED proposal without giving the customer, browser runtime, or an autonomous agent authority to set commercial terms.

## Roles

### Customer
Can only:
- read a quote that EVENTO has moved out of `draft` into a customer-visible state;
- read customer-facing versions and line items belonging to their own request;
- accept the exact current, non-expired quote version after scope approval;
- read their own acceptance record.

Customer cannot:
- create/update/delete quote prices;
- change current quote version;
- access `pricing_rules`;
- access `quote_version_economics`;
- change gross-margin/cost assumptions;
- treat quote acceptance as payment proof.

### EVENTO operator / owner-reviewed server workflow
Future privileged workflow may:
1. read approved scope and project complexity;
2. build line items from controlled pricing rules and explicit manual overrides;
3. create a new immutable `quote_versions` row rather than silently editing an old sent version;
4. attach `quote_items`;
5. calculate and store internal delivery-cost assumptions separately in `quote_version_economics`;
6. set `quotes.current_version_id`;
7. run validation checks;
8. move quote to `sent` only after owner/human commercial review.

This workflow must run server-side with least privilege. It must not put a service-role/secret key in the customer web runtime.

### Agent
An agent may propose:
- scope-to-line-item mapping;
- effort/risk notes;
- pricing recommendation ranges;
- cost estimates;
- commercial-risk flags.

An agent may not independently:
- send a binding quote;
- approve a discount outside configured policy;
- accept a quote for a customer;
- activate payment/fulfillment;
- self-approve its own pricing output.

## Version rules

A sent quote version is treated as immutable evidence. Changes require a new `version_number` and a new current version. Customer acceptance is tied to `quote_version_id`, terms version and an audit SHA-256 generated by the database acceptance RPC.

## Money rules

- Primary currency: AED.
- `subtotal_aed` = commercial subtotal before discount/tax.
- `discount_aed` is explicit and cannot exceed subtotal.
- `tax_aed` is explicit; EVENTO must not infer that tax is collectible merely because a tax field exists.
- `total_aed` is database-generated from subtotal - discount + tax.
- Internal expected variable cost and gross margin live only in `quote_version_economics`.

## Commercial state rules

Suggested quote lifecycle:
`draft → sent → accepted`

Exceptional terminal visibility states:
`expired`, `withdrawn`.

Acceptance requires:
- permanent authenticated customer;
- ownership match;
- quote status `sent`;
- exact `current_version_id`;
- unexpired version;
- `project_workflows.current_stage = scope_approved`;
- no prior acceptance for that version.

## Payment boundary

Quote acceptance does not equal payment. Gate 5 must create a provider-neutral `payment_order` tied to the accepted quote version. Fulfillment remains blocked until server-side verified payment state exists.

## Required evidence before enabling `EVENTO_COMMERCIAL_WRITE_MODE`

1. Apply Gate 0 hardening + Gate 3 migrations on isolated Supabase branch/test environment.
2. Test customer A cannot read quote B.
3. Test customer cannot INSERT/UPDATE/DELETE quote/version/item pricing.
4. Test customer cannot read internal economics/pricing rules.
5. Test stale/non-current/expired quote acceptance fails.
6. Test quote acceptance before `scope_approved` fails.
7. Test anonymous-auth user acceptance fails.
8. Test duplicate acceptance fails.
9. Re-run Supabase security/performance advisors.
10. Owner reviews the first generated quote fixture before enabling Preview writes.
